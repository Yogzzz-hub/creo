## 1. Purpose & Scope
This document defines the complete technical stack for Creo — a digital marketing agency management platform. Every tool, framework, service, and convention listed here is the source of truth for all development decisions. The AI coding agent must treat this document as authoritative and never deviate from these choices without explicit instruction.

Creo is a full-stack SaaS platform with two user-facing surfaces — a public marketing website and an authenticated portal — plus internal dashboards for creative teams, admins, and investors. The system handles client onboarding, content delivery workflows, real-time communication, payment processing, and business intelligence reporting.

## 2. Architecture Overview
Creo follows a monorepo architecture with two main applications sharing common types, utilities, and environment configuration. The frontend is a Next.js application; the backend is a Python FastAPI service. Both are deployed separately but developed in the same repository.

### 2.1 Repository Structure
creo/
├── apps/
│   ├── web/                  # Next.js 15 frontend
│   └── api/                  # Python FastAPI backend

│   └── utils/                # Shared utility functions

### 2.2 System Diagram
Request flow at a high level:
* Client browser → Vercel (Next.js frontend) → Railway (FastAPI backend) → Supabase (PostgreSQL + Auth + Storage + Realtime)
* Payments: Client → Razorpay (India) or Stripe (International) → webhook → FastAPI → Supabase
* Notifications: FastAPI → Resend (email) + MSG91 (WhatsApp + OTP SMS)
* Instagram Publishing: FastAPI → Instagram Graph API → Client Instagram account

### 4.2 API Design Conventions
* RESTful API — versioned under /api/v1/
* All responses use a consistent envelope: { data, error, meta }
* Authentication via JWT — token issued by Supabase Auth, validated in FastAPI middleware
* Role-based access control enforced at the router level using FastAPI dependencies
* All database operations are async using SQLAlchemy async sessions
* Background tasks (emails, WhatsApp messages, report generation) dispatched to Celery

## 6. Authentication & Authorisation

### 6.1 User Roles

| Role | Access Level |
|---|---|
| client | Own portal data only — deliverables, calendar (read), payments, add-ons, tickets, account |
| team_member | Tasks (own), calendar (own + assigned clients), live chat, deliverable submission |
| team_lead | Same as team_member + reassign tasks, view team metrics and performance |
| sales | Client profiles (read), pricing requests, AI brand analysis (read), sales pipeline |
| admin | Full access — all client data, all team data, reports, escalations, settings |
| investor_relations | Reports and financial data only — read-only |
| super_admin | All admin capabilities + demote admins, delete accounts, platform settings |

### 6.2 Session Timeouts
* client: 30 days
* team_member / team_lead / sales / investor_relations: 8 hours
* admin / super_admin: 4 hours

## 12. Technical Constraints & Hard Rules

### 12.1 Security
* SUPABASE_SERVICE_ROLE_KEY must NEVER be exposed to the frontend or committed to git
* All payment webhook endpoints must validate signatures before processing
* Instagram access tokens stored encrypted in the database — never in plain text
* All API endpoints (except /health and public webhooks) require valid JWT authentication
* Rate limiting on all auth endpoints — max 5 attempts per minute per IP

### 12.2 Performance
* All database queries must use async SQLAlchemy sessions — no synchronous DB calls in API routes
* Heavy operations (report generation, AI analysis, email/WhatsApp dispatch) must use Celery — never block the API thread
* Frontend images served via Next.js Image component with optimisation enabled
* API response time target: p95 under 500ms for all non-report endpoints

### 12.3 Data
* All timestamps stored in UTC — convert to local time in the frontend
* Soft deletes on client accounts (deleted_at column) — never hard delete client data
* File uploads go directly to Supabase Storage — never through the FastAPI server
* Max file sizes: images 10MB, videos 500MB — enforced on frontend before upload

### 12.4 Mobile
* The public website and client portal must be fully responsive — mobile-first design
* Bottom tab navigation on mobile for the client portal
* Touch targets minimum 44x44px on all interactive elements
