All copy and messaging across the site must reflect a growth partner positioning:

# MODULE 2
## Client Sign-up & Plan Selection

### 1. Module Overview

| Module Name | Client Sign-up & Plan Selection |
|---|---|
| Module Number | 2 of 16 |
| Type | Public-facing — minimal authentication |
| Primary Goal | Create client account, select plan, and gate entry to payment |
| Entry Point | Public site 'Get Started' CTA or /signup?plan=[tier] |
| Exit Point | Hands off to Module 3 — Payments & Onboarding |
| Authentication | Google Sign-in or Phone OTP via MSG91 |
| Dependencies | Module 1 (URL param pre-selection), Module 3 (payment gate) |

#### 1.1 Purpose
Lightweight account creation and plan selection. The goal is minimum friction to payment.
No questionnaire at this stage — brand data is collected post-payment in Module 3.

#### 1.2 Scope
* Account creation via Google OAuth or Phone OTP (MSG91)
* Plan selection from 3 predefined tiers
* Brief Terms & Conditions acknowledgement
* Handoff to Module 3 (payment)
* Email verification is NOT required at this stage. It is triggered only before payment in Module 3.

### 2. Sign-up Flow
Two-step flow with a progress indicator throughout.

#### 2.1 Step 1 — Account Creation

* **Authentication Options**
  * Google Sign-in — one-click OAuth via Google account
  * Phone Number / OTP — 6-digit code via MSG91 SMS, expires in 10 minutes

* **Fields Collected**

| Field | Required | Notes |
|---|---|---|
| Full Name | Yes | Used for account display and all communications |
| Email Address | Yes | Verified before payment in Module 3 |
| Phone Number | Yes (if not Google) | Required for OTP auth; optional if Google sign-in used |
| Business Name | Yes | Mandatory — pre-fills questionnaire in Module 3 |
| Password | No | Auth is via Google or OTP only — no password set |

If client arrives via `/signup?plan=growth`, the plan is pre-selected in Step 2 and the client is informed at the top of the form.

#### 2.2 Step 2 — Plan Selection
* Three plan cards — pre-selected plan highlighted if from URL param, but changeable
* Each card: tier name, monthly price, deliverable counts, key features, revision rounds, Instagram publishing
* 'Most Popular' badge on Growth tier
* Client must select exactly one plan to proceed — no default enforced
* 'Not sure? Book a call' link below cards — WhatsApp or phone

#### 2.3 T&C — Brief Acknowledgement
* Checkbox: 'I agree to the Terms & Conditions and Privacy Policy' — both linked
* Cannot proceed without ticking the box
* 'Create My Account' button submits and creates the account
* Full T&C (payment, refund, cancellation, revision policies) is presented in full before payment in Module 3.

### 3. Post Sign-up Behaviour

#### 3.1 On Successful Account Creation
* Account created with status: Pending Payment
* Client immediately redirected to Module 3 — payment flow
* Confirmation email dispatched: account details + selected plan summary + payment link

#### 3.2 Incomplete Sign-up — Automated WhatsApp Follow-up
Automated WhatsApp messages triggered via MSG91 at timed intervals after abandonment, followed by manual sales call if no response.

| Trigger | Automated WhatsApp (MSG91) | Manual Follow-up | Delay |
|---|---|---|---|
| Email entered, Step 1 not done | 'Hi [name], you started signing up — continue here: [link]' | Sales calls if no response in 24 hrs | 1 hour |
| Step 1 done, no plan selected | 'Your account is ready — choose your plan: [link]' | Sales calls if no response in 24 hrs | 2 hours |
| Plan selected, payment not done | 'You're one step away — complete payment to start growing: [link]' | Sales calls if no response in 24 hrs | 4 hours |

WhatsApp message templates must be pre-approved by Meta/WhatsApp Business before go-live. MSG91 handles the template submission process.

### 4. Technical & UX Requirements

#### 4.1 Progress Indicator
* Two steps: (1) Create Account → (2) Choose Your Plan
* Completed steps show tick; current highlighted; future muted

#### 4.2 Form Validation
* Inline field validation — errors beneath each field
* OTP expires 10 minutes; max 3 resends per session
* Duplicate email/phone detected on submission

#### 4.3 Security
* Google OAuth 2.0
* MSG91 OTP — 6-digit, 10-minute expiry
* HTTPS throughout; rate-limited account creation

#### 4.4 Responsiveness
* Mobile-first; plan cards stack vertically; OTP input optimised for numeric keyboard

| Attribute | Value |
|---|---|
| Account Status | Pending Payment |
| Email Verified | No — triggered in Module 3 before payment |
| Selected Plan | Stored — Starter / Growth / Pro |
| Business Name | Captured and stored |
| Questionnaire | Not started — triggered post-payment in Module 3 |
| Portal Access | No — granted only after payment confirmed |
| T&C | Brief T&C accepted — full T&C pending (Module 3) |

# MODULE 3
## Payments & Onboarding

### 1. Module Overview

| Module Name | Payments & Onboarding |
|---|---|
| Module Number | 3 of 16 |
| Type | Authenticated — requires account from Module 2 |
| Primary Goal | Verify email, collect full T&C, process payment, collect brand questionnaire, generate AI brand analysis |
| Entry Point | Redirect from Module 2 post account creation |
| Exit Point | Hands off to Module 5 — Onboarding Workflow & Content Pipeline |
| Authentication | Account created in Module 2 — session continues |
| Dependencies | Module 2 (account + plan), Module 4 (portal unlocked on completion) |

#### 1.1 Purpose
Module 3 bridges prospective and active paying client. It handles email verification, legal agreement, payment, and post-payment brand data collection.
Once complete, the client's creative team is assigned and the 7-day onboarding window begins in Module 5.

### 2. Onboarding Flow
4 sequential steps — cannot be skipped or reordered. Progress shown via a step indicator.

| Step | Name | Description |
|---|---|---|
| 1 | Email Verification | Client verifies email via a link sent to their inbox. |
| 2 | Full T&C Agreement | Client reads and agrees to full T&C including payment, refund, revision, and cancellation policies. |
| 3 | Payment | Client completes monthly payment via Razorpay (domestic) or Stripe (international). |
| 4 | Brand Questionnaire | 3-step questionnaire. AI brand analysis auto-generated on submission. |

#### 2.1 Step 1 — Email Verification
* On entry, system checks if email is verified; if not, dispatches verification email automatically
* Client clicks link — redirected back to Step 2; resend available after 60 seconds
* Verification link expires after 24 hours; cannot proceed without verified email
* Google OAuth clients are considered pre-verified — Step 1 is skipped automatically.

#### 2.2 Step 2 — Full Terms & Conditions
* Full T&C displayed as scrollable panel — client must scroll to bottom before 'I Agree' activates
* T&C agreement timestamped and stored against the client account
* Downloadable PDF copy available for the client to save
* Full T&C document is a placeholder — business owner to draft and provide before development begins.

#### 2.3 Step 3 — Payment

* **Payment Gateways**
  * Razorpay — domestic (India): UPI, card (Visa/Mastercard), net banking, wallets (PayTM, PhonePe)
  * Stripe — international payments: credit/debit card (Visa, Mastercard)
  * Gateway selection is automatic based on the client's billing country

* **Payment Behaviour**
  * On success: account status → Active; client redirected to Step 4 (Questionnaire)
  * On failure: error shown with option to retry or change payment method
  * Payment receipt emailed automatically on success
  * Subscription auto-renews monthly — client notified 3 days before renewal

* **Unsatisfied with Pricing — Sales Escalation**
  * 'Not satisfied with pricing? Contact our sales team' link on the payment screen
  * Clicking notifies the sales team immediately with client details and selected plan
  * Sales team contacts client via WhatsApp within 24 hours (handled in Module 6)

#### 2.4 Step 4 — Brand Questionnaire
Presented immediately after successful payment. Split into 3 grouped steps. Must be completed in one session.

| Step | Topic | Fields |
|---|---|---|
| 1 | Business Information | Business name (pre-filled), industry/sector, brief description, target audience demographics |
| 2 | Social Media & Presence | Instagram handle, Facebook page, TikTok (optional), other platforms, current posting frequency, what's working/not working |
| 3 | Content Goals & Brand Identity | Primary goal (awareness/sales/engagement), brand tone (multi-select), competitor references, topics to avoid, preferred style |

* Questionnaire answers are editable by the client within 7 days of submission from Account Settings.
* After 7 days, updates require a support ticket — admin applies the changes.

* **On Submission**
  * Questionnaire data stored against client account
  * AI brand analysis auto-generated immediately
  * Client sees confirmation: 'Your brand profile is ready — your team will be in touch within 7 days'
  * Client also sees a one-line brand summary on their portal dashboard: '[Tone] voice, targeting [audience], focused on [goal]'
  * Portal access unlocked — client can now log into Module 4
  * Admin and assigned creative team notified with the full AI analysis report

### 3. AI Brand Analysis

#### 3.1 Purpose
Auto-generated from questionnaire responses. Serves as an internal briefing document for the assigned creative teams before the 7-day brainstorming session.

#### 3.2 Analysis Output

| Output | Description |
|---|---|
| Brand Tone & Voice Summary | Recommended communication style — formal vs casual, energetic vs calm. Full version visible to creative team only; condensed one-liner shown to client. |
| Recommended Content Themes | 3–5 content topic pillars relevant to the client's industry, audience, and goals. |
| Audience Persona Summary | Target audience demographics and interests derived from questionnaire responses. |
| Content Goal Alignment | How the recommended content approach maps to the client's stated primary goal. |
| Reference Accounts | Competitor/reference accounts provided by client — flagged for creative team review. |

#### 3.3 Access Permissions

| Role | Access |
|---|---|
| Client | One-line summary only: '[Tone] voice, targeting [audience], focused on [goal]' — visible on portal dashboard |
| Assigned Graphics Team | Full access — visible in their task dashboard when assigned |
| Assigned Video Team | Full access — visible in their task dashboard when assigned |
| Admins | Full access — visible in client profile within admin panel |
| Sales Team | Read-only access — for context during client communications |
| Other Teams | No access |

### 3. Dashboard

#### 3.1 Activity Summary Strip
* Posters / Reels / Stories delivered vs planned / Open tickets

#### 3.2 Brand Summary Card
* Displays the client's AI-generated one-line brand summary from Module 3
* Format: '[Tone] voice, targeting [audience], focused on [goal]'
* 'Update profile' link navigates to Account > Business Profile

#### 3.3 Onboarding Progress Tracker (first 7 days only)
* Visible on dashboard during the 7-day onboarding window — automatically hidden after day 7
* Four milestone steps: Account created → Payment completed → Content plan received → Content plan approved

* Deliverables awaiting approval — count with 'Review Now' link

### 4. Deliverables

#### 4.1 Deliverable Types
* Posters — static image files
* Reels — short video files, playable inline
* Stories — static or animated image/video files

#### 4.2 List View
* Card grid or list — toggleable
* Filter by type and status
* Default: pending-approval first, sorted by submission date

#### 4.3 Deliverable Status Flow

| Status | Description |
|---|---|
| Pending Approval | Submitted by creative team — awaiting client review |
| Approved | Client approved — deliverable is downloadable |
| Rejected | Client rejected — revision task auto-created, escalated per Module 9 |
| Revision In Progress | Team working on revision following client rejection |
| Revised — Pending Approval | Revised version resubmitted — awaiting client re-review |

#### 4.4 Deliverable Detail View
* **Content Preview**
  * Posters/stories: full-size image display
  * Reels: inline video player — play, pause, seek
  * Download button: visible and active ONLY when status is Approved
  * File formats: Posters/Stories — JPG/PNG max 10MB; Reels — MP4 max 500MB

* **Approval Actions**
  * 'Approve' — marks approved, enables download, notifies creative team
  * 'Reject' — opens mandatory comment box; submission blocked without a comment
  * Comment box available on both approved and rejected deliverables

* **Revision Rounds by Plan Tier**

| Plan | Max Revision Rounds | After Max Rounds |
|---|---|---|
| Starter | 1 round | Admin intervenes if client rejects again |
| Growth | 2 rounds | Admin intervenes on third rejection |
| Pro | 3 rounds | Admin intervenes on fourth rejection |

* Download is locked until approval to prevent unapproved content being published.

### 5. Content Calendar
* Monthly grid view + list/agenda view — both read-only
* Each entry: content type icon, title, scheduled date, status
* Clicking entry opens linked deliverable or placeholder if pending

### 6. Payments

#### 6.1 Current Plan Card

#### 6.2 Payment History
* Table of past payments with 'Download Receipt' per row; failed payments show 'Retry'

#### 6.3 Plan Change
* Upgrade: prorated charge for remaining days in current cycle

### 7. Add-ons

* Contextual upsell prompts when monthly quota is exhausted

## Add-on & Upsell System

### 1. Module Overview

| Module Name | Add-on & Upsell System |
|---|---|
| Module Number | 16 of 16 |
| Type | Client-facing + internal |
| Primary Goal | Allow clients to purchase additional deliverables beyond their plan quota on a one-time basis |

#### 1.1 Purpose
The add-on system enables clients to purchase additional content units beyond their monthly plan without upgrading their full subscription.
This provides a low-friction upsell path ideal for product launches, seasonal campaigns, or content-heavy periods.

### 2. Available Add-ons

| Add-on | Unit | Price | Delivery SLA |
|---|---|---|---|
| Extra Poster | Per poster | TBD | 3 business days from purchase |
| Extra Reel | Per reel | TBD | 3 business days from purchase |
| Extra Story | Per story | TBD | 3 business days from purchase |

* Add-on pricing is uniform across all plan tiers — set and adjustable by admin from platform settings.

### 3. Purchase Flow

| Step | Action | Detail |
|---|---|---|
| 1 | Client browses add-ons | Navigates to /portal/addons — shows types, unit prices, and order form |
| 2 | Client selects type and quantity | Type (poster/reel/story) and quantity (1–10 units per purchase) |
| 3 | Client reviews order | Order summary: type, quantity, unit price, total. Optional content brief field. |
| 4 | Client pays | Immediate one-time charge via Razorpay (domestic) or Stripe (international) |
| 5 | Confirmation | Receipt emailed. In-portal: 'Your add-on order has been received — delivery within 3 business days.' Tasks auto-created. |

### 4. Task Creation & Capacity

#### 4.1 Automatic Task Creation
* On payment confirmation, tasks auto-created for each add-on unit
* Tasks tagged as 'Add-on' to distinguish from regular calendar tasks
* Follows same assignment logic — lowest load member within daily capacity
* Daily caps respected — add-on tasks count toward daily limit

#### 4.2 Delivery & Approval
* Add-on deliverables follow same submission, approval, and revision workflow as regular deliverables (Module 9)
* Appear in Deliverables section tagged as 'Add-on'
* Revision rounds for add-ons: 1 round regardless of plan tier
* Download unlocked on approval

### 5. Upsell Triggers

| Trigger | Upsell Prompt |
|---|---|
| Monthly posters quota exhausted | Banner: 'You've used all your posters this month. Need more? Add extra from [price] each.' |
| Monthly reels quota exhausted | Same prompt for reels |
| Monthly stories quota exhausted | Same prompt for stories |
| Client approves a deliverable | Subtle prompt: 'Love this? Get more this month — add extra [type] from [price].' |
| Client visits pricing/plan page | 'Not ready to upgrade? Top up with individual deliverables instead.' |
| Renewal approaching (3 days) | Email: 'Make the most of this month — add extra content before your cycle resets.' |

### 6. Admin & Reporting

#### 6.1 Admin Panel
* Add-on pricing configurable from admin settings — changes apply immediately
* All add-on orders visible in admin panel: client, type, quantity, amount, date, delivery status
* Admin can manually create an add-on order on behalf of a client

#### 6.2 Financial Reporting
* Add-on revenue tracked separately in financial report (Module 12) — 'Add-on Revenue' line item
* Add-on revenue included in KPI dashboard (Module 15) revenue section
* Per-client add-on spend visible in client profile — identifies high-value clients
