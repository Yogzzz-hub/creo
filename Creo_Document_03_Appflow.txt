## 1. Overview
This document maps every page, every navigation path, every user journey, and every redirect in the Creo platform. It is the authoritative reference for how screens connect and how users move through the product. The AI coding agent must use this document to implement navigation logic, route guards, and redirect behaviour.

Creo has three distinct surfaces sharing one domain:
* Public Website — unauthenticated, marketing-focused (creo.app, /about, /portfolio, /pricing, etc.)
* Client Portal — authenticated, for paying clients (/portal/*)
* Internal Dashboard — authenticated, for team members and admins (/dashboard/*, /admin/*, /kpi/*)

All three surfaces share a single login page at /login. After authentication, the user is routed to the correct surface based on their role. A client can never access internal routes, and a team member can never access client portal routes.

## 4. Authentication Flow
All users — clients and internal team — log in from the same page at /login. After authentication, the system reads the user's role from the JWT and routes them to the correct surface.

### 4.1 Login Flow
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | User visits /login | Login page shown — two options: 'Continue with Google' or 'Continue with Phone' |
| 2a | Google Sign-in | User clicks Google → Google OAuth popup → returns to /auth/callback → JWT issued → role-based redirect |
| 2b | Phone OTP | User enters phone number → MSG91 sends 6-digit OTP → user enters OTP → JWT issued → role-based redirect |
| 3 | Role-based redirect | client → /portal \| team_member / team_lead → /dashboard \| sales → /sales \| admin / super_admin → /admin \| investor_relations → /admin/reports |
| 4 | If onboarding incomplete | client with incomplete onboarding is redirected to the appropriate onboarding step instead of /portal — see Section 4.3 |

### 4.2 Sign-up Flow (New Clients Only)
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Visitor clicks 'Get Started' | Navigates to /signup (from nav, pricing CTA, or sticky bar) |
| 2 | Step 1 — Account Creation | /signup — client enters full name, email, phone, business name. Chooses Google or Phone auth. If arriving from /pricing?plan=growth, plan is pre-selected and shown. |
| 3 | Step 2 — Plan Selection | /signup/plan — three plan cards shown. Pre-selected plan highlighted. Client selects plan and clicks 'Continue'. |
| 4 | T&C Brief Acknowledgement | Checkbox on /signup/plan — 'I agree to T&C and Privacy Policy.' Cannot proceed without ticking. |
| 5 | Account Created | Account created with status: pending_payment. JWT issued. Client redirected to /onboarding/verify. |

### 4.3 Onboarding Flow (Post-Signup)
After account creation, clients must complete 4 onboarding steps before accessing the portal. The system checks completion state on every /onboarding/* and /portal/* request and enforces the correct step.

| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Email Verification | /onboarding/verify — verification email dispatched automatically. Client clicks link in email → redirected back to /onboarding/terms. Resend link available after 60 seconds. Google OAuth users skip this step. |
| 2 | Full T&C | /onboarding/terms — full T&C in scrollable panel. 'I Agree' button activates only after scrolling to bottom. T&C acceptance timestamped and stored. |
| 3 | Payment | /onboarding/payment — Razorpay (India) or Stripe (international) payment modal. On success → /onboarding/questionnaire. On failure → error with retry. 'Not satisfied with pricing?' link → triggers sales team notification. |
| 4 | Brand Questionnaire | /onboarding/questionnaire — 3-step questionnaire (business info → social presence → content goals). All 3 steps on one page with step indicator. On submit → AI analysis generated → /onboarding/complete. |
| 5 | Complete | /onboarding/complete — confirmation screen: 'Your brand profile is ready — your team will be in touch within 7 days.' CTA: 'Go to your dashboard' → /portal. |

The onboarding gate: any request to /portal/* from a client with incomplete onboarding is intercepted by middleware and redirected to the correct pending step.
The check order is: verify → terms → payment → questionnaire.
A client who has paid but not completed the questionnaire goes to /onboarding/questionnaire, not /portal.

### 4.4 Logout
* Logout link available in: client portal sidebar (Account section), internal dashboard sidebar (bottom)
* On logout: JWT invalidated, Supabase session cleared, user redirected to /login
* Inactive session timeout: client 30 days, internal roles 8 hours, admin 4 hours — on expiry, redirected to /login with a 'Session expired' message

## 5. Core User Journeys

### 5.1 Journey 1 — New Client: Discovery to First Content
The most important end-to-end journey. A potential client discovers Creo, signs up, pays, and receives their first content.

| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Lands on creo.app | Sees hero with 'See Our Plans' CTA and 'Book a Call' CTA. Scrolls through How It Works, stats strip. |
| 2 | Visits /pricing | Reviews 3 plan cards. Clicks 'Start Growing' on Growth plan. |
| 3 | Arrives at /signup?plan=growth | Growth plan pre-selected. Completes account creation with Google or Phone. |
| 4 | Plan confirmed at /signup/plan | Growth plan shown as pre-selected. Ticks T&C checkbox. Clicks 'Create My Account'. |
| 5 | Redirected to /onboarding/verify | Verification email sent. Client clicks link. Redirected to /onboarding/terms. |
| 6 | Completes /onboarding/terms | Scrolls full T&C. Clicks 'I Agree'. |
| 7 | Completes /onboarding/payment | Pays via Razorpay (UPI/card). Payment confirmed. |
| 8 | Completes /onboarding/questionnaire | Fills 3 steps. Submits. AI analysis generated. |
| 9 | Arrives at /onboarding/complete | Sees confirmation. Clicks 'Go to your dashboard'. |
| 10 | Lands on /portal | Sees dashboard with onboarding progress tracker (Steps 1–2 complete, Steps 3–4 pending). Brand summary card shown. |
| 11 | Day 1–3 (internal) | Creative team delivers content plan. Client receives in-portal + email notification. |
| 12 | Client reviews content plan | /portal/calendar — views draft calendar entries. Approves the plan. |
| 13 | Day 7 (internal) | Tasks formally assigned to creative team. 3-business-day SLA starts. |
| 14 | Client receives deliverable notification | In-portal + email: 'Your poster is ready for review.' |
| 15 | Client reviews at /portal/deliverables/[id] | Views deliverable. Clicks 'Approve'. Download unlocked. |

### 5.2 Journey 2 — Client: Reviewing and Rejecting a Deliverable
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Client receives notification | In-portal alert + email: 'Your reel is ready for review.' |
| 2 | Opens /portal/deliverables | Sees deliverable card with status 'Pending Approval'. Clicks to open. |
| 3 | Opens /portal/deliverables/[id] | Reel plays inline. Client watches and decides to reject. |
| 4 | Clicks 'Reject' | Rejection comment box appears. Field is required — cannot submit without a comment. |
| 5 | Submits rejection | Status → Rejected. Revision task auto-created. 24-business-hour clock starts internally. |
| 6 | Client sees status update | Deliverable card now shows 'Revision In Progress'. |
| 7 | Team member submits revision | Client receives notification: 'Your revised reel is ready for review.' |
| 8 | Client reviews revised version | /portal/deliverables/[id] — new version shown. Client approves. |
| 9 | Status → Approved | Download button becomes active. Client can download the file. |

### 5.3 Journey 3 — Client: Purchasing an Add-on
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Client sees upsell prompt | After approving a poster, prompt appears: 'Love this? Get more this month — add extra posters from [price].' Or client navigates directly to /portal/addons. |
| 2 | Opens /portal/addons | Sees 3 add-on types (poster, reel, story) with unit prices and quantity selector. |
| 3 | Selects 2 extra reels | Quantity set to 2. Optional content brief field filled or left blank. |
| 4 | Clicks 'Buy Now' | Order summary shown: 2 x Reel = [total]. Razorpay/Stripe payment modal opens. |
| 5 | Payment confirmed | Receipt emailed. In-portal: 'Your add-on order has been received — delivery within 3 business days.' |
| 6 | Tasks auto-created internally | 2 reel tasks created and assigned to video editor. |
| 7 | Add-on deliverables appear | /portal/deliverables — two new reel cards tagged 'Add-on' with status 'Pending Approval'. |

### 5.4 Journey 4 — Client: Raising a Support Ticket
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Client clicks 'Raise a Ticket' | From dashboard quick-access or /portal/support → new ticket form opens. |
| 2 | Selects ticket type | Dropdown: Deliverable Revision / General Support / Billing Issue / Content Brief Update. |
| 3 | Fills form | Subject, description, optional file attachment. For deliverable revision — links specific deliverable. |
| 4 | Submits ticket | Ticket created with status 'Open'. Confirmation shown. Unique ticket ID generated. |
| 5 | Routed internally | General Support / Billing → chatbot first. Deliverable Revision → creative team + admin notified directly. |
| 6 | Client receives update | In-portal + email notification on every status change. |
| 7 | Client replies in thread | /portal/support/[id] — ticket detail page. Client can send messages, attach files (max 25MB). Team replies in same thread. |
| 8 | Ticket resolved | Status → Resolved. Client can reopen within 7 days if issue recurs. |

### 5.5 Journey 5 — Team Member: Completing a Task
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Team member logs in | /login → role = team_member → redirected to /dashboard. |
| 2 | Reviews today's tasks | /dashboard/tasks — 'Today's Tasks' tab shown by default. Tasks sorted by client priority tier. |
| 3 | Opens a task | /dashboard/tasks/[id] — task card shows: client name, deliverable type, content brief from AI analysis + content plan, due date. |
| 4 | Marks 'In Progress' | Status updated. Task clock noted internally. |
| 5 | Uploads completed file | File upload field on task card. Clicks 'Submit Deliverable'. File sent to Supabase Storage. |
| 6 | Deliverable pushed to portal | Client receives notification. Status → 'Pending Approval' in both team and client views. |
| 7 | Client approves | Task status → Approved. Team member sees confirmation on task card. |
| 7b | Client rejects | Task status → Revision. Team member sees rejection comment. 24-hour clock shown on task card. |

### 5.6 Journey 6 — Admin: Managing an Escalation
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Admin receives escalation alert | In-portal notification + email: SLA breached on task #[ID] for client [name]. |
| 2 | Opens /admin/escalations | Active escalations listed with severity, client, team member, SLA breach time. |
| 3 | Reviews escalation detail | Clicks escalation → sees task, delivery history, and client context. |
| 4 | Takes action | Reassigns task to another team member OR contacts client via WhatsApp to explain delay. |
| 5 | Marks escalation resolved | Escalation status → Resolved. Timestamp logged for weekly report. |

### 5.7 Journey 7 — Incomplete Sign-up Recovery
| Step | Action / Screen | Detail |
|---|---|---|
| 1 | Visitor starts sign-up | Enters email on /signup but closes the browser before completing Step 1. |
| 2 | 1 hour later — automated WhatsApp | MSG91 sends: 'Hi [name], you started signing up — continue here: [link]' |
| 3 | No response after 24 hours | Sales team receives notification in /admin or /sales — manual WhatsApp call initiated. |
| 4 | Client returns via link | Clicks link in WhatsApp → lands on /signup with email pre-filled → completes sign-up. |
| 5 | Sales marks follow-up done | In sales dashboard, lead status updated. |

## 6. State, Edge Cases & Empty States

### 6.1 Route Guards — Access Control
| Scenario | Behaviour |
|---|---|
| Unauthenticated user visits /portal/* | Redirected to /login. After login, redirected back to originally requested URL. |
| Unauthenticated user visits /dashboard/* | Redirected to /login. |
| Authenticated client visits /dashboard/* | Redirected to /portal (403 not shown — silent redirect). |
| Authenticated team member visits /portal/* | Redirected to /dashboard (403 not shown — silent redirect). |
| Client with incomplete onboarding visits /portal/* | Redirected to the next pending onboarding step. |
| Client with lapsed subscription visits /portal/* | Portal loads in read-only mode. Banner shown: 'Your subscription has lapsed. Renew to restore full access.' CTA → /portal/payments. |
| Admin visits any route | Admin has access to all /admin/*, /kpi, and /dashboard/* routes. |
| Investor Relations visits /admin/* | Access granted only to /admin/reports. All other /admin/* routes redirect to /admin/reports. |

### 6.2 Empty States
| Page / State | Empty State Content |
|---|---|
| /portal/deliverables — no deliverables yet | Illustration + 'No content yet — your team is working on your first batch.' Message shows expected delivery date if within 7-day window. |
| /portal/deliverables — filter returns no results | 'No [type] deliverables match your filter.' Link to clear filter. |
| /portal/support — no tickets | 'No tickets yet. Need help?' with 'Raise a Ticket' button. |
| /portal/calendar — no entries | 'Your content calendar is being set up — check back after your content plan is approved.' |
| /portal/addons — no past orders | 'No add-on orders yet.' with add-on type cards shown to encourage first purchase. |
| /dashboard/tasks — no tasks today | 'No tasks due today.' with 'View Upcoming Tasks' link. |
| /admin/escalations — no active escalations | Green banner: 'All clear — no active escalations.' with count of escalations resolved this week. |
| /admin/clients — no clients | 'No clients yet. Share your pricing page to get started.' |

### 6.3 Loading States
* All data-fetching pages show skeleton loaders — not spinners — while content loads
* Deliverable detail page: video player shows a loading skeleton before the file URL resolves
* Payment pages: 'Processing...' overlay shown after payment submission to prevent double-clicks
* AI analysis generation: /onboarding/complete shows an animated progress indicator while analysis is generated (typically 3–8 seconds)
* Report pages: skeleton table rows shown while report data loads

### 6.4 Error States
| Error | Handling |
|---|---|
| Payment failed | Error message shown inline on /onboarding/payment or /portal/payments. 'Retry' button and 'Try a different method' link. Subscription status remains pending. |
| File upload too large | Frontend validation before upload attempt. 'File exceeds maximum size (10MB for images, 500MB for videos).' |
| Instagram connection expired | Banner on /portal and /portal/account/instagram: 'Your Instagram connection has expired. Reconnect to continue publishing.' CTA → reconnect flow. |
| OTP expired | 'Your code has expired. Request a new one.' Resend button available immediately. |
| Network error on API call | Toast notification: 'Something went wrong. Please try again.' With retry button where applicable. |
| 403 — wrong role for route | Silent redirect to role-appropriate home (not a 403 page — better UX). |
| 404 — page not found | Custom /404 page with Creo branding and link back to home. |
| 500 — server error | Custom /500 page: 'Something went wrong on our end. We've been notified.' Link to /portal or home. |
