# Team lead audit fixes (bug.pdf, October 15)

1. **Dispatch persistence:** dashboard dispatch and task-board creation use POST `/tasks`. Client and specialist UUIDs, title, format and brief are saved together. Assigned tasks enter production; unassigned cards enter backlog. The server rejects inactive, foreign-agency and foreign-pod specialists. Both views invalidate the shared pod query after successful saves.
2. **Roster workload:** each member's arrow opens an accessible workload dialog, including on mobile. It uses that member's persisted assignments, status and deadlines. Roster counts use `active_wip` rather than a nonexistent count field.
3. **Leave return navigation:** both the lead's approvals/schedule page and the personal leave-request page have a dashboard return link.
4. **Calendar refresh:** remove the header refresh button. The calendar automatically refetches every 15 seconds, on focus, and after its mutations.
5. **Queue cancellation:** queued tests have a confirmed Cancel action backed by a row lock shared with worker claims. Repeated cancellation is safe. Scheduled production rows expose the existing cancel action directly. Processing, published and uncertain submissions cannot be deleted through these controls. Canceled rows remain as history; this does not delete posts already on Instagram.
6. **Obsolete freelance entry point:** remove the SLA warning's Monitor button. The old `/freelance-management` URL redirects to the lead task board; there is no standalone management page mounted at that URL. Freelancer accounts retain their own assigned-work interface.
7. **Channel input:** channels no longer require a selected direct-message contact to enable the composer, emoji or send controls, or display fetched messages. Failed sends restore the draft.
8. **QA synchronization:** dashboard review cards derive from persisted uploads instead of an always-empty local array. Dashboard, task board and QA poll shared pod data. QA metrics show loading/error states instead of false zeros. Tasks in production appear in QA only after a creative uploads the finished asset; the empty state explains this and shows the production count.

Validation: full backend suite (141 passed, 32 skipped, 3 subtests); separate real PostgreSQL regression proves dispatch persists across sessions and a submitted upload enters the lead QA queue with the correct member workload. Browser checks with mocked API responses cover UUID submission, reload visibility, desktop/mobile workload dialogs, channel typing and sending, leave navigation, automatic calendar UI and test cancellation. TypeScript and Vite production build pass. No production posts were sent or production records modified during verification.
